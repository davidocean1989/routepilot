# RoutePilot｜01 用户需求与完整 User Journey

## 1. 核心用户需求
用户表面上说的是：

> “帮我排一下这些地点。”

但真正需求可以拆成四层：

### Functional Need
帮我找一个更合理的访问顺序。

### Efficiency Need
不要让我自己逐个在地图里试路线。

### Confidence Need
让我相信这个顺序是真的更合理，而不是 AI 随便排的。

### Execution Need
算完以后我可以直接开始走，而不是重新手动输入地图。

如果 RoutePilot 只输出地点顺序，用户还需要自己打开地图重新搜一次，那产品闭环是不完整的。

## 2. 核心触发场景
### 场景 A：出发前一晚规划
用户已经知道明天想去哪些地方，但不知道顺序。

### 场景 B：早上临时规划
用户已经到了目的地，临时决定今天去哪几个地方。

### 场景 C：攻略收集后整理路线
用户从小红书/朋友推荐中收集了几个地点，但没有形成路线。

### 场景 D：多人同行，需要统一方案
多人提出多个地点，最后需要形成一条大家都能看的路线并发到微信群。

## 3. 用户输入设计
V1 应尽可能允许用户直接说一句话。

示例：

> “我明天从杭州西湖出发，想去南浔古镇、乌镇、西塘古镇，晚上住上海静安寺附近。”

系统自动提取：

```text
起点：杭州西湖
目的地：
- 南浔古镇
- 乌镇
- 西塘古镇
终点：上海静安寺附近
```

如果有歧义，再追问必要问题。

原则：

> **能推断的先推断，只对影响路线结果的重要歧义追问。**

## 4. 完整 User Journey
### Stage 1｜产生旅行计划
用户已经决定当天想去多个地方。

用户心理：

> “这些地方都想去，但不知道怎么排。”

### Stage 2｜输入地点
用户自然语言输入起点、多个目的地、可选终点。

### Stage 3｜地点确认
系统展示：

> 我理解你的路线是：起点 / 途经点 / 终点

用户确认。

### Stage 4｜路线计算
系统后台：
1. Geocode；
2. 获取地点坐标；
3. 计算所有点两两之间的距离 / 时间；
4. 运行路线优化算法；
5. 对候选路径计算真实路线成本；
6. 得到推荐顺序。

### Stage 5｜结果展示
第一屏优先展示：
- 推荐路线
- 总里程
- 总预计驾驶时间
- 相比原始顺序节省的里程 / 时间

### Stage 6｜地图查看
用户点击“查看完整路线”，进入 RoutePilot H5 页面。

地图上显示：
- 起点
- 途经点
- 终点
- 顺序编号
- 完整路线

### Stage 7｜微信分享
用户点击“分享路线”，生成可分享 URL。

同行者点击后，无需重新输入地点，直接看到同一条路线。

### Stage 8｜实际出发
用户点击：

> **开始导航**

优先路径：
- 如果地图 App 支持起点 + 多个途经点 + 终点，则一次性把整条路线交给地图 App。

Fallback：
- 如果地图 App 不支持完整多途经点，则 RoutePilot H5 保持完整 itinerary，并按段唤起导航。

产品边界：
- RoutePilot 决定“先去哪、后去哪”；
- 地图 App 决定“这一段具体怎么开”。

## 5. 理想闭环
```text
想到多个地点
   ↓
输入一句话
   ↓
确认地点
   ↓
RoutePilot 排序
   ↓
查看结果
   ↓
地图可视化
   ↓
分享给同行人
   ↓
当天打开
   ↓
拉起地图导航
   ↓
完成路线
```

## 6. User Journey 关键风险
### 风险 1：地点歧义
同名 POI 或模糊名称可能导致错误解析。

解决：
- 地点标准化
- 城市/行政区筛选
- 必要时追问确认

### 风险 2：用户不信算法结果
需要展示节省里程/时间，并提供简短解释。

### 风险 3：地图链接体验不好
如果需要用户复制地址到地图 App，体验会断掉。

### 风险 4：不同设备/地图 App 能力不一致
需要 Navigation Adapter + Preferred/Fallback Path。

### 风险 5：结果过于复杂
第一版只突出：顺序、里程、时间、地图、导航。

## 7. V1 核心 User Stories
### US-01
作为旅行用户，我希望输入一天想去的多个地点，系统自动告诉我最合理的访问顺序，这样我不用自己反复比较路线。

### US-02
作为旅行用户，我希望看到优化后的总里程和时间，这样我能判断路线是否合理。

### US-03
作为旅行用户，我希望看到完整路线地图，这样我能直观理解当天行程。

### US-04
作为旅行用户，我希望把路线发给同行人，这样所有人看到的是同一套计划。

### US-05
作为旅行用户，我希望点击“开始导航”后可以进入地图 App，并尽可能按 RoutePilot 给定的顺序完成路线。
