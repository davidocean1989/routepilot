# 04｜Technical Spike 03：路线优化验证

项目：Davidocean · AI Career / RoutePilot（一趟跑完）  
副标题：一天跑 6 个地方，怎么走最顺？  
验证日期：2026-09-12（Asia/Shanghai）  
状态：**小规模静态矩阵优化验证通过；时间收益对矩阵采样时刻敏感。**

## 1. 结论

固定杭州出发、上海结束，在南浔、乌镇、西塘三个中间地点的全部六种顺序中，主快照的最短时间路线为：

**杭州 → 乌镇 → 南浔 → 西塘 → 上海**

| 指标 | 原顺序：杭州→南浔→乌镇→西塘→上海 | 主快照最优顺序 | 节省 |
| --- | ---: | ---: | ---: |
| 总行驶时间 | 12138 秒（3小时22分18秒） | 11936 秒（3小时18分56秒） | 202 秒（3分22秒），1.66% |
| 总行驶里程 | 229701 米（229.701 km） | 219006 米（219.006 km） | 10695 米（10.695 km），4.66% |

本次主快照的最短时间与最短里程顺序相同，但其他两份已有矩阵的时间最优顺序均为原顺序。**算法能够找到给定矩阵下的全局最优解，但本例不能证明稳定节省 3 分 22 秒。**

没有调用新地图请求，没有消耗新地图查询额度；没有开发完整应用或保留生产优化器。实验使用一次性 Python 计算，交付报告、结果和核验记录。

## 3. 方法与全部候选

三个中间地点共 3!=6 种排列。逐一计算四条相邻有向边的成本之和，完整枚举后比较，即可证明当前约束、当前矩阵下的最优性，不依赖启发式猜测。

```text
路径：[0, p1, p2, p3, 4]
总时间：T[0,p1] + T[p1,p2] + T[p2,p3] + T[p3,4]
总距离：D[0,p1] + D[p1,p2] + D[p2,p3] + D[p3,4]
```

最优路线逐段核算：

| 路段 | 时间（秒） | 距离（米） |
| --- | ---: | ---: |

完整六条路线、逐段成本、基线和收益见 [optimization-results.json](../spike-03-evidence/optimization-results.json)。单次枚举及逐段汇总测得约 0.329 ms，不含文件读取与写入；这是本地一次测量，不作为性能基准或服务响应时间承诺。

## 4. 独立核验

已执行以下核验，结果见 [verification.json](../spike-03-evidence/verification.json)：

1. 输入文件哈希匹配，时间和距离均为 5×5 有限非负数矩阵。
2. 20 条非对角有向边逐项与 Spike 02 原始 MCP 响应匹配；单位直接沿用秒和米。
3. 六条候选无重复、固定起终点，均覆盖全部五个地点且只有四条边；六组总成本与显式列出的路线计算一致。
4. 使用独立的动态规划递推再次求最优时间与最优距离，两者均与穷举结果一致。递推以“当前位置、剩余中间点”为状态，剩余为空时只返回到固定终点的成本。
5. 核对节省绝对量、比例和展示单位。

这些核验验证本次实验结果，不等同于通用优化器的完整测试。未实现生产输入校验器，缺失矩阵、不可达点、非法索引、多个最优解等通用行为仍需在后续实现时测试。本次输入已经完整有效。

## 6. 规模与下一步建议

五个总地点、固定起终点时只有六个候选；若六个总地点则有 4!=24 个，八个总地点为 6!=720 个。这里与“八个可排列途经点”的 8!=40320 不同。枚举成本约为 O((n−2)!×n)，随可排列地点数阶乘增长。本次只实测五点，不以组合数推算替代更大规模性能测量。

**建议通过 Spike 03，采用穷举作为小规模路线优化的基准方法。** 当前已有“真实地点→矩阵→有向路线排序→基线比较”的完整实验链路。后续若进入最小产品链路，应优先固定输入输出约定：地点身份与顺序、固定起终点、优化目标、矩阵版本、四段成本、总量与基线收益；输入不完整时明确失败。

正式实现前仍需验证：缺失/不可达边、异常输入、相同成本的确定性输出、真实出行约束，以及新矩阵下排名变化的展示方式。矩阵采集继续沿用 Spike 02 已验证的分批与节流方案。本次不进入完整应用开发，也不以实验脚本作为生产实现。

## 7. 最小复现片段

以下为一次性验证代码，仅使用 Python 标准库；从项目目录执行即可在标准输出列出六条候选，不写入原始输入。

```python
import json
from itertools import permutations
from pathlib import Path

p = json.loads(Path('docs/spike-02-evidence/spike-03-input.json').read_text())
start, end = p['start_index'], p['end_index']
middle = [i for i in range(len(p['points'])) if i not in (start, end)]
rows = []
for perm in permutations(middle):
    order = [start, *perm, end]
    pairs = list(zip(order, order[1:]))
    seconds = sum(p['duration_s'][a][b] for a, b in pairs)
    meters = sum(p['distance_m'][a][b] for a, b in pairs)
    rows.append((seconds, meters, order))
for row in sorted(rows):
    print(row)
```

预期第一条输出为 `(11936, 219006, [0, 2, 1, 3, 4])`。报告数据均来自已保存腾讯矩阵的本地计算，没有引入示例路程或推测时间。
