## 请求与响应结构、单位

原生工具 matrix，必填 from/to/mode 均为字符串；多个坐标用分号分隔，mode=driving。SDK 外层 content[].text 包含 JSON 字符串；structured_content=null；is_error=false 仍可能包含业务错误。

成功业务结构：status=0、message=Success、request_id、result.rows[i].elements[j]。本次成功单元只有 distance 和 duration，没有路线摘要、道路列表、polyline 或单元 status 字段。行对应 from 顺序、列对应 to 顺序；按请求顺序组装并检查数量，接口不回显点名。

**distance 单位为米，duration 为秒**，依据 [TencentLBS 官方参考](https://github.com/TencentLBS/tencentmap-webservice-skill/blob/main/references/api-direction.md)，本轮返回数值与该定义一致。响应没有自描述单位；不能仅由数值推导单位。directionDriving 的 duration 为分钟，与矩阵不同。

## 边界与频控结论

实测接受 1×1、1×4、4×1、2×2、1×5。5×5 两次均返回 120。8×8、50×2、51×2、2×50、2×51、25×25、26×25、1×200、1×201 也均为 120，没有取得参数超限错误，因此不能宣称验证了最大合法值或拒绝边界。

官方参考列出一对多 ≤200，多对多每侧 ≤50、乘积 ≤625。这是文档限制，当前账号的实测硬上限仍未知。大批次在请求间隔 5 秒后仍失败，小批次成功，提示容量可能按点对工作量计算；这是推断，未访问账号控制台，不能确定精确 QPS、剩余额度或计费规则。未做额度耗尽或压力测试。

## 对 V1 的影响

真实多点方向成本可通过原生 matrix 分批取得；本轮五个 1×5 批次验证了五地点数据通路。当前账号不能直接假定单次 5×5/8×8 可用。建议接入层按小批次节流，对 120 有限退避并缩批；鉴权错误停止，业务状态非零不作为矩阵解析。无路、缺失字段和异常单元不得补零或直线距离。保留行级请求时间和来源，避免把分批结果描述成同一时刻快照。

尚待账号控制台或腾讯确认矩阵点对配额，再复测单次 5×5 与合法/超限边界。此项不阻碍本轮分批数据已取得的结论，但总状态保持 PARTIAL。
